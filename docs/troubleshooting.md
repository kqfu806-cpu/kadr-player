# Решение проблем

Сначала проверьте, что сервер отвечает:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

В ответе есть число треков, выбранная папка и статус Ollama. Сообщения backend записываются с ротацией в `cache/errors.log`; серверный вывод при запуске через `run.bat` находится в `cache/server.log`.

## Приложение не запускается

1. Убедитесь, что установлен Python 3.10 или новее:

   ```powershell
   python --version
   ```

2. В корне проекта восстановите виртуальное окружение и зависимости:

   ```powershell
   python -m venv venv
   .\venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. Запустите сервер вручную, чтобы увидеть ошибку:

   ```powershell
   .\venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
   ```

4. Если порт уже занят, закройте другой экземпляр Курымдык или проверьте процесс, слушающий порт 8000. Не завершайте неизвестный процесс без проверки.

## Не удаётся выбрать папку или библиотека пустая

- В верхней панели нажмите **Папка…** и выберите каталог, доступный текущему пользователю Windows.
- Убедитесь, что в нём есть поддерживаемые аудиофайлы. Сканер читает локальные метаданные; неизвестные или повреждённые файлы могут быть пропущены.
- Ответ `POST /api/scan` содержит число найденных треков. Выберите папку заново после перемещения библиотеки.

## Ollama offline или не найдена модель

Локальное воспроизведение не требует Ollama. При её недоступности рекомендации продолжают работать по локальной истории и эвристикам; AI-описания и семантическое ранжирование могут быть отключены.

1. Проверьте, что Ollama запущена и доступна на `http://127.0.0.1:11434`.
2. Проверьте установленные модели:

   ```powershell
   ollama list
   ```

3. Если нужной модели нет, установите только требуемую модель:

   ```powershell
   ollama pull nomic-embed-text
   ollama pull deepseek-r1:8b
   ollama pull llava:7b
   ```

`nomic-embed-text` используется для эмбеддингов, `deepseek-r1:8b` — для текстовых AI-задач, `llava:7b` — для визуальной проверки обложек. Страница здоровья вернёт статус и список обнаруженных моделей.

## Last.fm не возвращает данные

- Задайте `LASTFM_API_KEY` в `.env` по образцу `.env.example` и перезапустите сервер.
- Проверьте `.tools/lastfm.log`. При сетевой ошибке или HTTP 429 клиент повторяет запрос; если есть сохранённый ответ возрастом до семи дней, он может использоваться как резерв.
- После истечения этого срока без API-ключа или доступа к Last.fm новые данные получить нельзя. Уже работающие локальные функции останутся доступны.

Не публикуйте содержимое `.env` или ключ Last.fm в логах и сообщениях.

## Deezer или MusicBrainz недоступен

- Подборка недели может вернуть пустые списки и записи об ошибках, когда Deezer недоступен или не находит релизы. Попробуйте обновить позже.
- При недоступном источнике обложки плеер пробует доступные локальные/встроенные данные и другие источники, затем показывает плейсхолдер.
- Профиль артиста может не показать недавние релизы без MusicBrainz ID или при сетевой ошибке; биография и локальные треки не требуют MusicBrainz.

Состояние источников и ошибки доступны в `cache/errors.log`; подробные ошибки Last.fm — в `.tools/lastfm.log`.

## Статистика сообщает, что база занята

SQLite-lock отвечает HTTP 503 с сообщением повторить запрос. Закройте другие процессы, которые одновременно записывают `cache/stats.sqlite3`, и повторите действие. Убедитесь, что папка `cache/` доступна для записи. Не удаляйте базу: в ней хранится история прослушиваний и эмбеддинги.

Неожиданная ошибка API возвращает общее сообщение без внутренних деталей; traceback записывается в `cache/errors.log`. После исправления причины безопасно повторите запрос.

## Волна или подборка пустая

- Сначала просканируйте музыкальную папку; волна и недельная подборка используют текущую библиотеку.
- При первом запуске эмбеддинги рассчитываются в фоне. Очередь волны доступна и до их готовности, но семантическое ранжирование будет ограничено.
- У волны не повторяются уже выданные элементы текущего цикла; после исчерпания доступного списка цикл начинается снова.
- Last.fm и Deezer требуют интернет-доступа для новых внешних рекомендаций; ранее закэшированные ответы могут временно помочь.

## Замена edited-трека недоступна

- Проверьте интернет и наличие `yt-dlp` из `requirements.txt` в активном `venv`.
- Ищите кандидатов только после завершения сканирования и проверяйте канал, название и длительность. Внешние версии могут отличаться от нужного мастера.
- URL вне YouTube, файл свыше 50 МБ или несоответствие длительности будут отклонены. Это ограничение намеренное.
- Для замены требуется явное подтверждение. Исходник должен остаться в `archive/censored/`; проверьте доступность папки для записи.

## Тесты не стартуют в Windows

Установите dev-зависимости и запустите тесты из виртуального окружения:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\python.exe -m pytest
```

Если системная временная папка недоступна, задайте тестам локальный каталог:

```powershell
.\venv\Scripts\python.exe -m pytest -p no:cacheprovider --basetemp .tools\pytest-local-temp
```
